# intuitive/

Design references written as pictures rather than prose.

These are not specifications of what the editor does. They are statements of what
it *should feel like*, drawn out case by case, so that "this feels wrong" can be
turned into "this case, this picture" — and so that the answer is agreed before
any code is written to chase it.

Each document shows the same three states for every situation:

1. **Before** — the starting arrangement
2. **Naive** — what happens when the feature is switched off, or absent
3. **Ideal** — what a person would draw by hand if they were tidying up after you

The gap between 2 and 3 is the whole feature. The gap between 3 and what the
editor actually does is the backlog.

---

## A note on the diagrams

Most of the "naive" pictures were **generated by the editor's own stampers**
rather than drawn by hand, so the damage they show — merged borders, eaten
letters, `┼` where a line crossed a wall — is exactly what really happens rather
than an artist's impression of it.

Every diagram is checked mechanically: no corner in any of these documents leads
anywhere it does not connect, except inside "naive" blocks, where a broken join
*is* the point being made.
